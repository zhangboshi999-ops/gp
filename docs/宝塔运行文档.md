# 宝塔（BT）环境运行文档

本文针对**宝塔面板**环境，从零把本项目跑起来。全部操作都尽量在面板里点，点不到的地方给命令。

配套模板都在 `deploy/` 目录：

| 文件 | 用途 |
| --- | --- |
| `deploy/bt-nginx-rewrite.conf` | 后端 PHP 站点的 Nginx 伪静态 |
| `deploy/bt-nginx-proxy.conf` | H5 静态站 + `/api` 反代后端 + `/ws` 反代 WebSocket |
| `deploy/bt-supervisor.conf` | WebSocket 与 tick 的常驻进程配置 |
| `deploy/pm2-ecosystem.config.js` | 同上，用 PM2 管理器时用它 |
| `deploy/start-bt.sh` | 宝塔版一键启停实时行情 |
| `tools/sync_kline_batch.sh` | 批量补日线（`sync kline` 只支持单只） |

---

## 0. 最终拓扑

```
浏览器 ──► H5 站点 (Nginx 静态 web/dist)
             ├── /api  ──► PHP 站点 (fastadmin/public)  ──► MySQL(stock)
             └── /ws   ──► socket/server.js:9502  ◄── Redis  ◄── php think quote:tick
```

学习阶段最简方案：**H5 与后端放在同一个站点** —— `npm run dev` 本地跑（方案 A），或构建后放到同域 `/h5/` 子目录（**方案 B**，省掉反代配置）。生产再拆成两个站点（方案 C）。

## 1. 安装软件（软件商店）

| 软件 | 建议版本 | 必须 | 说明 |
| --- | --- | --- | --- |
| Nginx | 1.20+ | 是 | Apache 也可，伪静态用 `.htaccess`（仓库已有） |
| MySQL | 5.7 或 8.0 | 是 | 记下 root 密码 |
| PHP | 7.4 ~ 8.2（**8.1 最稳**） | 是 | **必须装 redis 扩展**，否则实时行情起不来 |
| Redis | 6+ | 推荐 | 不装也能跑，只是没有实时推送 |
| phpMyAdmin | 任意 | 推荐 | 导 SQL 用；也可直接用面板「数据库 → 导入」 |
| PM2 管理器 或 进程守护管理器 | — | 推荐 | 守护 socket 与 tick 进程 |
| Node 版本管理器 | 18+ | 是 | 跑 socket 服务、打包前端 |

> PHP ≥ 8.3 时 ThinkPHP 5 会有兼容性警告，建议选 **PHP 8.1**。

**安装 redis 扩展**：软件商店 → 已安装的 PHP → 安装扩展 → `redis` → 安装 → 重启 PHP。
验证：

```bash
/www/server/php/81/bin/php -m | grep -i redis     # 输出 redis 即成功
```

**检查禁用函数**：PHP → 禁用函数，确认没有 `proc_open`、`putenv`、`exec`（部分面板默认禁了 `exec`，一般不影响本项目）。

## 2. 上传代码

```bash
# 方式一：面板上传（根目录 ZIP 太大时先在本地打包）
# 方式二：服务器直接拉
cd /www/wwwroot
git clone <你的仓库地址> stock
```

目标结构：

```
/www/wwwroot/stock/
├── fastadmin/     ← 后端（Web 根目录要指到里面的 public）
├── web/           ← 前端源码
├── socket/        ← WebSocket 服务
├── db/            ← 必导的业务表 SQL
├── tools/         ← 批量补日线、导出种子数据
├── deploy/        ← 本文用的各种模板
└── docs/          ← 本文档

> 目录里已自带 `vendor/`，**不需要 composer install**。若你自行用 Git 托管，别把 `vendor/` 写进 `.gitignore`。

**设置权限**（宝塔建站会自动处理一部分，手动补一次更保险）：

```bash
cd /www/wwwroot/stock
chown -R www:www .
find . -type d -exec chmod 755 {} \;
find . -type f -exec chmod 644 {} \;
chmod -R 775 fastadmin/runtime fastadmin/public/uploads runtime
chmod +x deploy/*.sh tools/*.sh
```

## 3. 导入数据库

面板 → 数据库 → 新建数据库：

```
数据库名：stock
用户名：  stock（或 root）
字符集：  utf8mb4
```

然后按顺序导入 **3 个** SQL（`面板 → 数据库 → 导入` 或 phpMyAdmin）：

| 顺序 | 文件 | 内容 |
| --- | --- | --- |
| ① | `fastadmin/fastadmin.sql` | 框架表（22 张，含后台菜单/管理员） |
| ② | `db/business_schema.sql` | **业务表结构（15 张，必须有）** |
| ③ | `db/business_seed.sql` | 标的数据 257 条 / 新股 / 交易员 / 客服问答 |

> ⚠️ `fastadmin.sql` 里**不含**本项目的 fa_stock、fa_account、fa_order 等业务表，只导它会报「表不存在」。

大文件导入被限制时：面板 → PHP → 上传限制改到 100M、`max_execution_time` 改 300，或用命令行：

```bash
/www/server/mysql/bin/mysql -uroot -p stock < db/business_seed.sql
```

导入后应有 **37 张表**，`fa_stock` 有 **257** 行。

## 4. 建站点（后端 PHP）

面板 → 网站 → 添加站点：

| 项 | 值 |
| --- | --- |
| 域名 | `stock.example.com`（本地可用 `stock.test` + hosts） |
| 根目录 | `/www/wwwroot/stock/fastadmin/public` ← **一定要到 public** |
| PHP 版本 | PHP-81 |
| 数据库 | 不创建（前面已建） |

> 没有域名时：宝塔可直接用「服务器 IP」建站；想用 `stock.test` 这种假域名，需在**本机** hosts 加一行 `服务器IP  stock.test`（Windows：`C:\Windows\System32\drivers\etc\hosts`；Mac/Linux：`sudo vi /etc/hosts`）。

建好后逐项设置：

1. **网站目录**：根目录与「运行目录」**二选一，不要重复套一层**
   - 根目录 = `/www/wwwroot/stock/fastadmin/public` → 运行目录**留空**
   - 根目录 = `/www/wwwroot/stock/fastadmin` → 运行目录填 `/public`
2. **伪静态**：粘贴 `deploy/bt-nginx-rewrite.conf` 的内容并保存
3. **防跨站攻击(open_basedir)**：先**关闭**排查期间再按需开启（开着容易报 `No input file specified`）
4. **SSL**（可选）：Let's Encrypt 免费证书，开启后记得勾强制 HTTPS
5. **上传限制**：PHP → 上传限制改 ≥ **8M**；Nginx 站点「配置文件」里加 `client_max_body_size 8m;`（付款收据上传要用）

验收：

```bash
curl http://stock.example.com/api/market/lists?limit=1
# 返回 {"code":1,...} 说明后端 OK
```

**后台入口**：`http://stock.example.com/ujWLHBNEfM.php/index/login`
（随机文件名在 `fastadmin/public/` 下，上线建议改成不易猜的名字）

## 5. 配置后端连接

`fastadmin/.env`（没有就复制 `.env.sample` 改名，或新建，参考第 4 节库名密码）：

```ini
[database]
hostname = 127.0.0.1
database  = stock
username  = root
password  = 你的MySQL密码
hostport  = 3306
prefix    = fa_
```

`fastadmin/application/extra/redis.php` —— 与宝塔 Redis 保持一致：

```php
'host' => '127.0.0.1',
'port' => 6379,
'ws_port' => 9502,      // 必须与 socket 服务的 WS_PORT 一致
```

宝塔 Redis 若设了密码，把 `password` 填上；同时 socket 服务的 `REDIS_URL` 写 `redis://:密码@127.0.0.1:6379`。

改完清缓存：

```bash
cd /www/wwwroot/stock/fastadmin
/www/server/php/81/bin/php think clear --cache --temp
```

**其他常用配置**：

| 文件 | 改什么 |
| --- | --- |
| `application/extra/payee.php` | 充值收款账户、各链地址、汇率、限额 |
| `application/extra/lang.php` | 语言开关 |
| `application/extra/market.php` | 行情数据源 Key（留空用内置演示数据） |
| `application/config.php` | `default_timezone` 建议改 **`Asia/Tokyo`**（默认 `PRC`，日本股票时间会差 1 小时） |

## 6. 跑前端 H5

### 方案 A：开发模式（推荐先跑这个）

```bash
cd /www/wwwroot/stock/web
npm install --registry=https://registry.npmmirror.com
npm run dev -- --host 0.0.0.0
```

`vite.config.js` 里改代理目标：

```js
proxy: {
  '/api': { target: 'http://stock.example.com', changeOrigin: true },
  '/ws' : { target: 'ws://127.0.0.1:9502', ws: true }
}
```

访问 `http://服务器IP:5173`（宝塔安全 → 放行 5173）。

### 方案 B：同域部署（最省事，推荐先看这个）

不用建第二个站点、不用配反代：

```bash
# 1) 指定子目录基路径：在 vite.config.js 的
#    export default defineConfig({ 下面加一行   base: '/h5/',
cd /www/wwwroot/stock/web
grep -q "base:" vite.config.js || sed -i "0,/defineConfig({/s//defineConfig({\n  base: '\/h5\/',/" vite.config.js

# 2) 构建并复制到后端 public 下
npm run build
cp -r dist /www/wwwroot/stock/fastadmin/public/h5
```

访问 `http://stock.example.com/h5/` 即可 —— 接口同域走 `/api`，天然无跨域问题。
WebSocket 若走反代，见方案 C 的 `/ws` 段（同域时可让前端直连 `ws://域名:9502`，放行端口即可）。

> sed 在某些系统上不认换行转义，若没插入成功，直接用编辑器在 `export default defineConfig({` 下一行手写 `  base: '/h5/',`。
> 改回独立站点部署时，把 `base: '/h5/'` 删掉即可。

### 方案 C：独立静态站 + Nginx 反代（生产推荐）

```bash
cd /www/wwwroot/stock/web
npm run build                      # 产物 web/dist
```

面板 → 网站 → 添加**静态站点**：

```
域名：h5.example.com
根目录：/www/wwwroot/stock/web/dist
```

再在该站点的「配置文件」里，把 `deploy/bt-nginx-proxy.conf` 中 `location /api/`、`location /ws`、`location /uploads/` 三段粘进 `server { }` 里（Upstream 改成你后端站点的真实端口，同域则用 `127.0.0.1:80`）。

> WebSocket 反代**必须**带 `Upgrade`/`Connection` 头，否则详情页右上角会一直显示「○ 离线」。

## 7. 实时行情常驻

先确认 Redis 已启动：**软件商店 → Redis → 启动**（或 `systemctl start redis`）。

> 两点建议：① 宝塔 → Redis → 设置 → **设密码**（随后同步改 `extra/redis.php` 的 `password` 与 socket 的 `REDIS_URL`）；② 性能设置里开启 **AOF 持久化**，否则 Redis 重启会丢实时缓存（历史日线在 MySQL，不受影响）。

### 方式一：一键脚本（最快）

```bash
cd /www/wwwroot/stock
PHP_BIN=/www/server/php/81/bin/php ./deploy/start-bt.sh start
PHP_BIN=/www/server/php/81/bin/php ./deploy/start-bt.sh status
```

### 方式二：PM2 管理器（推荐，能开机自启）

宝塔 → 软件商店 → 安装 PM2 管理器 → 打开后：

```bash
cd /www/wwwroot/stock
pm2 start deploy/pm2-ecosystem.config.js
pm2 save
pm2 startup        # 按提示再执行一次输出的命令
```

### 方式三：进程守护管理器（Supervisor）

**① 安装插件**：软件商店 → 搜索「进程守护管理器」→ 安装（付费插件；不想买见下面 ④ 的手工 Supervisor）

**② 先查真实路径**（面板里填的命令必须是绝对路径）：

```bash
which node                       # 宝塔 Node 版本管理器装的通常是 /www/server/nodejs/v18.x/bin/node
ls /www/server/php/              # 看实际 PHP 版本目录，如 81 → /www/server/php/81/bin/php
```

**③ 添加两条守护进程**：插件主界面 → 「添加守护进程」，按下表逐项填（不同版本字段名略有差异，意思一样）

| 字段 | 第一条（WebSocket） | 第二条（行情 tick） |
| --- | --- | --- |
| 名称 | `stock-socket` | `stock-tick` |
| 启动用户 | `www` | `www` |
| 运行目录（Directory） | `/www/wwwroot/stock/socket` | `/www/wwwroot/stock/fastadmin` |
| 启动命令（Command） | `/www/server/nodejs/v18/bin/node server.js` | `/www/server/php/81/bin/php think quote:tick` |
| 进程数量 | 1 | 1 |
| 自动启动 / 自动重启 | 开启 | 开启 |
| 环境变量（如果有该输入框） | `WS_PORT=9502,REDIS_URL=redis://127.0.0.1:6379` | 留空 |
| 日志文件 | `/www/wwwroot/stock/runtime/socket.log` | `/www/wwwroot/stock/runtime/tick.log` |

> ⚠️ **界面里没有「环境变量」框时**，用 `env` 前缀写在命令里（Supervisor 不走 shell，不能用 `A=1 node` 这种写法）：
> ```
> /usr/bin/env WS_PORT=9502 REDIS_URL=redis://127.0.0.1:6379 /www/server/nodejs/v18/bin/node server.js
> ```
> Redis 有密码时写成 `redis://:密码@127.0.0.1:6379`。

保存后点「启动」，状态应为 `RUNNING`；若立刻 `FATAL/Exited`，点日志按钮看输出（九成是路径写错或 `runtime` 目录 www 不可写）。

**④ 没有该插件时的手工 Supervisor（免费）**

```bash
# CentOS
yum install -y supervisor && systemctl enable --now supervisord
# Ubuntu/Debian
apt install -y supervisor && systemctl enable --now supervisor

# 复制仓库自带模板（按实际路径改一遍）
cp /www/wwwroot/stock/deploy/bt-supervisor.conf /etc/supervisor/conf.d/stock.conf
supervisorctl update
supervisorctl status              # 看到 stock:stock-socket / stock:stock-tick RUNNING
supervisorctl restart stock:*     # 改完配置或改了 market.php 后用它重启
```

> 无论用哪种方式，**改了 `market.php`、`redis.php` 之后一定要重启这两个进程**，配置是在启动时读进内存的。

**端口放行**：宝塔安全 → 放行 `9502`（若 H5 跨机器连 WS）与 `5173`（开发模式）。

验收：

```bash
curl http://127.0.0.1:9502/health      # 返回 pong / ok
tail -f runtime/tick.log
```

### 保活（可选计划任务）

面板 → 计划任务 → shell 脚本，每 5 分钟：

```bash
cd /www/wwwroot/stock && PHP_BIN=/www/server/php/81/bin/php ./deploy/start-bt.sh start >> /dev/null 2>&1
```

脚本自身做了幂等判断，重复执行不会起多个进程。

进程保活 + 行情同步的完整建议见下一节（**不要把 `sync all` 放进定时任务**，太慢）。

## 8. 数据同步命令与定时任务

### 8.1 命令速查（`cd /www/wwwroot/stock/fastadmin` 后执行）

| 命令 | 作用 | 写进哪张表 | 注意 |
| --- | --- | --- | --- |
| `php think sync quote` | 拉**当前报价**（现价/涨跌/成交量） | `fa_stock` | 支持 `--market=TSE`、`--code=7203`；东京 230 只约 6 分钟 |
| `php think sync kline --code=7203` | 拉该股**日线 K**（默认 90 根） | `fa_stock_kline`（`period=1d`） | **必须带 `--code`，一次只能一只**；会先删该股旧日线再写入 |
| `php think sync index` | 首页五大指数（日经/TOPIX/S&P…） | `fa_stock` | 走 Twelve Data，需要 `twelvedata.apikey` |
| `php think sync crypto` | BTC/ETH/USDT 报价 | `fa_stock` | 加 `--kline=1` 连加密 K 线一起拉 |
| `php think sync profile` | 基本面（市值/PE/PB/股息） | `fa_stock` | 走 Twelve Data，耗额度最多 |
| `php think sync all` | 报价 + 指数 + 加密 + **逐只股票日线** | 全部 | 最慢（含全市场日线），**不要放定时任务** |

> quote 管「列表上的价格」，kline 管「详情页的 K 线图」，两者不是一回事。

### 8.2 批量补日线（kline 只支持单只，用配套脚本）

```bash
cd /www/wwwroot/stock
export PHP_BIN=/www/server/php/81/bin/php
export DB_PASS=你的MySQL密码

./tools/sync_kline_batch.sh               # 首页热门标的（is_hot=1）
./tools/sync_kline_batch.sh -n 50         # 按权重取前 50 只
./tools/sync_kline_batch.sh 7203 6758     # 指定代码
```
日志：`runtime/sync_kline.log`。每只之间默认停顿 2 秒（`SLEEP=2` 可调），避免触发免费源限流。

### 8.3 建议的定时任务（宝塔 → 计划任务）

任务类型统一选 **Shell 脚本**，执行用户 `root`（或 `www`，需保证目录可写）。

| 名称 | 周期 | 脚本内容 | 说明 |
| --- | --- | --- | --- |
| 实时进程保活 | 每 5 分钟 | `cd /www/wwwroot/stock && PHP_BIN=/www/server/php/81/bin/php ./deploy/start-bt.sh start` | 幂等，重复执行不会起多个进程 |
| 东京报价刷新 | 每 30 分钟 | `cd /www/wwwroot/stock/fastadmin && /www/server/php/81/bin/php think sync quote --market=TSE` | 一轮约 6 分钟，30 分钟周期不会重叠 |
| 日线补充 | 每天 18:00 | `cd /www/wwwroot/stock && PHP_BIN=/www/server/php/81/bin/php DB_PASS=密码 ./tools/sync_kline_batch.sh -n 50` | 50 只约 3 分钟 |
| 指数与加密 | 每天 09:00 | `cd /www/wwwroot/stock/fastadmin && /www/server/php/81/bin/php think sync index && /www/server/php/81/bin/php think sync crypto` | 需要 Twelve Data key |
| 清理缓存 | 每周一次 | `cd /www/wwwroot/stock/fastadmin && /www/server/php/81/bin/php think clear --cache --temp` | 改了配置文件后手动清即可 |
| **数据库备份** | 每天 03:00 | 宝塔计划任务类型选「**备份数据库**」→ 选 `stock` → 保留 7 份 | 别用 shell 手写，面板自带更稳 |
| **日志清理** | 每周一次 | `find /www/wwwroot/stock/runtime -name "*.log" -mtime +7 -delete` | tick/socket/sync 日志会持续增长 |
| **K 线清理** | 每天 04:00 | `cd /www/wwwroot/stock && ./tools/clean_kline.sh -d 30` | 分钟线只增不减，见 8.4 |

**防重叠（可选）**：给耗时任务加文件锁，避免上一轮没跑完下一轮又启动：

```bash
flock -n /tmp/stock_sync.lock -c 'cd /www/wwwroot/stock/fastadmin && /www/server/php/81/bin/php think sync quote --market=TSE >> /www/wwwroot/stock/runtime/sync_quote.log 2>&1'
```

**三条纪律**
1. 定时任务里 PHP、node 一律写**绝对路径**（`/www/server/php/81/bin/php`），cron 没有面板的环境变量
2. 不要把 `sync all` 放进定时任务（含全市场日线，可能半小时以上）
3. 免费数据源有速率限制，任务周期别短于单轮耗时

### 8.4 数据增长与清理（K 线会一直涨，必须处理）

`fa_stock_kline` 里两种数据的增长特性完全不同：

| 周期 | 谁写入 | 是否增长 | 说明 |
| --- | --- | --- | --- |
| `1d` 日线 | `php think sync kline --code=xxx` | **不增长** | 先 DELETE 该股旧日线再写入 90 根，每只恒定约 90 行 |
| `1m` 分钟线 | `quote:tick` 实时进程（`QuoteStream::persistBar`） | **持续增长** | 每个订阅标的每分钟一行，只增不减 |

分钟线只对**有人正在看的标的**生成（`QuoteStream::activeCodes()` 从 Redis 读订阅集合，没人打开详情页就不写），所以日常量不大。但两种情况会让它快速膨胀：

- 用 `php think quote:tick --codes=...` 固定跑一批标的（不受订阅限制）
- iTick 拉不到数据时会自动降级为**模拟数据**，此时**不限交易时段**、24 小时持续写

**粗估**（单行约 200 字节，含索引）：

| 场景 | 日增行数 | 年增体积 |
| --- | --- | --- |
| 同时 10 只被订阅（正常） | 约 1.4 万 | 约 1 GB |
| 固定跑 50 只 | 约 7 万 | 约 5 GB |
| 固定跑全量 257 只 | 约 37 万 | 约 25 GB ⚠️ |

查询性能不用担心 —— 表上已有复合索引 `idx_code_period_time (code, period, time)`，详情页按 code + period + time 取数走索引，百万行内毫秒级。真正的问题是**磁盘与备份体积**。

**清理脚本**（已实测）：

```bash
cd /www/wwwroot/stock
./tools/clean_kline.sh --dry       # 先看会删多少行（强烈建议先跑这个）
./tools/clean_kline.sh -d 30       # 保留最近 30 天分钟线
./tools/clean_kline.sh -d 7        # 只留 7 天
./tools/clean_kline.sh -d 90 -p 5m # 也可清理其它周期
```

- 只删分钟线，**不动日线**（日线由 `sync kline` 自行覆盖刷新）
- 分批删除（每批 5000 行），不会长时间锁表
- 优先用 `mysql` 客户端，找不到则自动用 PHP 的 mysqli；数据库信息自动读 `fastadmin/.env`
- 每月 1 号自动 `OPTIMIZE TABLE`（日线覆盖写入会产生碎片）
- 日志在 `runtime/` 下，建议配合每周的日志清理任务

## 10. 宝塔常见报错

| 现象 | 原因 / 处理 |
| --- | --- |
| 首页 404，只有根路径能开 | 伪静态没生效 → 粘贴 `deploy/bt-nginx-rewrite.conf` 并重载 Nginx |
| `No input file specified` | 根目录没指到 `public`，或开了 `open_basedir` 防跨站 → 先关掉验证 |
| 接口 500 空白 | 看 `fastadmin/runtime/log/`；多数是 `.env` 库名密码错或 `runtime` 不可写 |
| 后台能开但样式乱 | 站点根目录错误，静态资源被 PHP 接管；确认根目录 = `.../fastadmin/public` |
| `quote:tick` 起不来 / 报缺扩展 | PHP 没装 redis 扩展，或 CLI 用的 PHP 与站点不是同一个（用 `/www/server/php/81/bin/php` 绝对路径） |
| WS 一直「○ 离线」 | 9502 没放行 / socket 没运行 / Nginx 缺 `Upgrade` 头；看 `runtime/socket.log` |
| 上传收据失败 | `fastadmin/public/uploads` 属主改 `www`，PHP 上传限制 ≥ 8M |
| 数据不对或看不到股票 | 忘了导 `db/business_schema.sql`、`business_seed.sql`，或没跑 `php think sync quote` / `sync all` |
| 磁盘涨得快 / 备份变大 | `fa_stock_kline` 的 `1m` 分钟线只增不减；跑 `./tools/clean_kline.sh -d 30` 并挂每日定时任务 |
| Redis 连不上 | 宝塔 Redis 未启动 / 有密码未在 `extra/redis.php` 与 `REDIS_URL` 填写 |
| K 线图空白 / 只有分时 | 该股没跑过 `sync kline`（日线为空）；用 `./tools/sync_kline_batch.sh -n 50` 补日线 |
| K 线时间/开盘时间差 1 小时 | `application/config.php` 的 `default_timezone` 是 `PRC`，改成 `Asia/Tokyo` 后清缓存 |
| 上传报 413 / 收据传不了 | PHP 上传限制 < 8M，或 Nginx 缺 `client_max_body_size 8m` |
| `/h5/` 打开空白或 404 | `vite.config.js` 没设 `base: '/h5/'`，或 dist 没放到 `fastadmin/public/h5` |
| Redis 设密码后 socket 连不上 | `REDIS_URL` 要写成 `redis://:密码@127.0.0.1:6379`（冒号不能漏） |
| 多个 tick 进程 CPU 飙高 | `pgrep -f "think quote:tick"` 查重，多余的 `pkill -f` 掉，改用 PM2 守护 |

## 11. 上线前的安全建议

1. 后台入口 `ujWLHBNEfM.php` 改名，并在 Nginx 里限制内网 IP 访问
2. `.env`、`runtime/`、`.git` 禁止外部访问（宝塔默认已禁 `.env` 需确认）
3. 数据库不要用 root，给 `stock` 库单独账号
4. 全站 HTTPS，H5 的 WebSocket 相应改用 `wss://`
5. 关闭 `app_debug`（`fastadmin/application/config.php` 里 `app_debug => false`）
6. 宝塔面板自身：改默认端口与入口路径、开基本认证；定期升级面板
7. Redis **只监听 127.0.0.1**（宝塔 Redis 设置里关掉外网监听），并设强密码；不要把它暴露到公网
8. 数据库与代码定期备份（宝塔计划任务：备份数据库 + 备份目录，保留 7~30 份）
